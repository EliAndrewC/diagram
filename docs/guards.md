# The guards: what is enforced, where, and why

*Project reference, split out of [`../CLAUDE.md`](../CLAUDE.md) so it is loaded on demand rather
than in every session's context. CLAUDE.md keeps the one-row-per-guard table; this file is the
full record - the rule, the mechanism, the measurement that motivated it and the GM's ruling - and
the doctrine for writing a guard.*

**Load this file when:** a guard blocked or rewrote a command and its message did not settle the
question, you are adding or changing a guard, or you are auditing what the guards cost
(`make audit`). The economics of the whole set are in [`efficiency-tooling.md`](efficiency-tooling.md).

---

Every guard has a test companion that `make hooks-test` runs as a gate phase; a guard without one
turns the gate red (constitution XVIII).

## Writing a guard

**A GUARD THAT CAN PRODUCE THE COMPLIANT COMMAND SHOULD PRODUCE IT** (GM 2026-08-30: *"are there
places where a makefile command is refusing to do something but a tool could do a rewrite or return
additional context or whatever?"*). A `PreToolUse` hook may return `updatedInput` - the command
REWRITTEN - and `additionalContext` - a line the model reads - both at exit 0 and both costing
nothing, while exit code 2 costs a model round trip. The ladder:

- **REWRITE** where the guard already names the compliant command in its own refusal (`make-only`,
  `no-poll`, `pair`, `house-style`, `main-tree`, `clone-sync`'s stale head). Never guess: a shape the
  matcher cannot rebuild exactly keeps the refusal, because a wrong rewrite costs a session its
  command while a refusal costs one turn.
- **TEACH FIRST, FREE** where a block cannot be avoided but the lesson can arrive earlier
  (`guard-file` at Read time, `batching` one turn below its bar, `measure` on the first run).
- **STAY A REFUSAL** where the action is destructive or irreversible, or the refusal IS the content:
  `repo-safety`, `source-block`, `readme`, `discard`, `clone-sync`'s name-routing and live-claim,
  `no-branch`, and the blocks inside `measure` and `gate`. `specs/164-guards-that-correct/research.md`
  R3 records why for each, and R6 does the same for the Makefile's own refusals - nearly all ask for
  a DECISION (a written reason, an authorization at a terminal, a procedure), which no substitution
  can supply.

**Do the right thing and say so** (GM 2026-09-07: *"anytime we are able to say that a command was run
incorrectly and then supply the correct thing to do, then it is at least possible that what we should
do is simply do the correct thing and then inform the session through hook context that we have done
it"*). The verdict is made PER REFUSAL BRANCH rather than per guard, because a guard-level verdict
converts one branch and leaves the rest unexamined:
`specs/212-guards-that-do-the-right-thing/research.md` R1 classifies every branch, and the corpus
`scripts/fixtures/guard-refusals-2026-09.json` is replayed by `tests/tooling/test_guard_corpus.py`.
What stays refused, and why: `make-only`'s `guard-write` and `guard-file`'s no-marker (the compliant
form is an Edit carrying a REASON, which only the session has), `batching` (the fix is to make fewer
turns, which no rewrite of one command can do), and the destructive or decision-shaped refusals
above.

**An escape is an invocation too.** Every guard's BLOCKING decision is anchored through
[`scripts/_hookmatch.py`](../scripts/_hookmatch.py), and every token matched in a COMMAND goes through
`_hookmatch.py escape <TOKEN>`, which blanks heredocs and quoted strings, drops search-command
segments and drops `for VAR in` word lists. The census of which tokens those are is DERIVED
(`tests/tooling/test_guard_firing_log.py`): it enumerates every `*_OK` in `scripts/` and the skill
Makefile and fails on any that is not classified as `command`, `content` (a marker inside edit
text), `environment` (read as `${TOKEN:-}`, which a mention cannot set), `make-variable` or
`not-an-escape`; a second check fails the build if a guard ever decides a command escape by
substring. Why it matters: the escape RATE is the statistic this project acts on, and `measure`
clears its counter and `gate` removes its state file on the escape branch, so a session grepping for
a token to learn how the escape works would otherwise switch the guard off for its next command. The
one deliberate exclusion, stated at the point of change: `pair`'s AGENT-PROMPT branch, because a
prompt is prose with no command grammar.

**When you add a guard**, three properties, each learned by getting it wrong: match INVOCATIONS not
mentions (seven false positives in one feature - a grep, a commit message, a docstring, a fixture
argument, a redirect, a test harness, and a hook that blocked its own repair); check the ESCAPE FIRST
or the guard cannot be repaired through the channel it guards; and prove it FIRES by deleting it and
watching a test go red.
