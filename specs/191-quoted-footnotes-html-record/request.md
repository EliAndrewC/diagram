# Feature 191 - the GM's request, verbatim (2026-09-06, via /goal)

> Okay. So here is something that I would now like. It's great that we are citing sources. However, what would be even better is To have references which quote those sources. So for example, if we are saying that chicken coops existed in Imperial China, but not in Imperial Japan, then that is probably two different citations, each of which could have a quote from the source from which we got that information. This would make the references section much longer, but we could put these in footnotes at the bottom of the page.  So I would like you to do the following three things now.
>
> First: add this as a new rule going forward for our references; Anytime we add a new reference in order to support something, then in our references section, we quote the passage or passages from the reference which support the assertion that we are making. There is no point in including a reference if it is not being quoted. This should not only be a requirement, but should involve a subagent check, which I believe is already the case for our references in general since it is important for us to ensure that our summary of a source matches what the source actually says. In this case, we would be having our subagent checks confirm both that we have quoted the source accurately and also that the quotation supports the assertion in our write up, which the quote is included to cite a source for, and that every relevant assertion has a footnote link, even if this means multiple footnote links per paragraph or even multiple per sentence in sentences which make multiple assertions.
>
> Second, we want to go back to all of our existing references and backfill these quotations from our existing sources. We can pull the quotes, which support the points that we are making and then run the subagent checks on those quotations to ensure they match.
>
> Third: I believe that this new and improved reference section is better served through making our references section HTML rather than markdown. The reason for this is that HTML would give us greater ability to do things like have footnotes with links in which moving your mouse over the link pulls up the actual footnote and its quote as a tooltip. This is something which many blogs do, especially ACOUP (A Collection of Unmitigated Pedantry), Bret Devereau's excellent blog about history. doing footnotes in this way also makes it easier to have footnote links multiple times per paragraph.  So please convert our references sections to HTML and make the links on our HTML maps. link to the files locally rather than linking to the markdown on GitHub since the markdown on GitHub will no longer exist as it has been replaced with HTML. Thanks.
