> I have just realized a dmypy Damons. Each take up something like four hundred to six hundred megabytes of RAM. While this makes sense because we get nearly three seconds of savings on Our quick tests alone, We are now eating up multiple gigabytes of RAM for all of our concurrent Claude code sessions because the daemon that we are using only supports a single module copy. So we cannot have a single version of the daemon pointing at all of the different clones that we have. However, I have just learned that There are apparently some new rust based myPy checkers. So while the myPy that we are using is essentially the reference implementation, switching over to a Rust solution is going to be so fast that we probably won't even need the daemon at all. Right? can you look into this? pick one of those and then test it out to see how well it works. I realized that it's possible that we might need to make some changes or something. like, it might have slightly different requirements. Just, like, different dentures have different requirements, but I think this would be better. In particular, my guess is that this would be so fast that we would not need a daemon at all and that we need a daemon because the reference implementation, which is written in Python, is slow enough that it requires one, but that a rust based solution would be so fast as to not need one. So I think that this is worth checking. Can you do that as an experiment and report your findings? this will be a new spec kit feature, of course. and I can take acceptance of this before we merge it back into main. because, of course, we will need to make sure that we are happy with what we have picked and what the performance impact is. But I think saving multiple gigabytes of RAM makes it worth the overall effort. I realized that the Rust based solutions are not as mature, but I think for our needs, that is fine. We are essentially doing... some static code analysis to catch a few errors earlier in the process rather than making heavy use of this. So even if there are some features that are not quite up to snuff, as long as we have a tool that isn't actively crashing or whatever, then I think that is good enough for the needs of this specific project.
