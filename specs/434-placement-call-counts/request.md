# Feature 434 - the GM's request, verbatim

The GM, 2026-10-27, after T57's check-in on feature 417:

> Can you break down those 18.3 million calls for me by category? I mean, you've given me a few of the categories so far. 780,000 calls for the notice board, 604,000 calls per well, etc. But I'm really curious how the total amount breaks down. Of course, I realize that it is not possible to give me complete numbers without overlaps, because, you know, if you think about it, the one function call to generate a Hamlet overlaps with literally everything. But, you know, I'm not asking for it to literally add up to the exact number, but, like, if you go by the different phases, for example, that are listed at dev/placement-stages/hamlet-placement.html then I would love to know how many function calls occur in each phase for the 40 homestead placement that we are talking about. And of course, some of those will be literally zero, because some of them only apply for certain map types. But you know, if you went down the list, then I would love to see a list of those phases with function call counts next to them. In fact, that might be a good thing for our tooling to be able to produce. because the whole point of that breakdown is that we are able to display an automatically generated list of our procedures. And so having tooling that is able to not only measure these things, but actually perhaps even insert that kind of table into that document, I think would be pretty helpful to me. Now, admittedly, I don't think that we need or even want to literally have that document be always up to date with the exact count. But for now, let's say that this document will be generated to have the most recent counts that happen to have been captured. For each of those stages on 40 Homestead Hamlet. And therefore, if we happen to have not measured any of the stages, because we happen to have not generated a 40 homestead hamlet of a type that contains the stage, then we just show a dash or something. But I think it would be helpful to me to look at what we are doing and then have the call count displayed at each stage, and then also at the very end of the document to have a table that shows a list of the stages and the call counts for each, and then maybe the percentage of the total that each of those stages represents in terms of call count. Again, I realize that call count is different than time, but I think that I would rather have call count and percentage of call count and actually exclude the time, at least for now. How does that sound? Does that sound doable?

The session answered with the per-stage table and proposed the tooling, offering per-step counts (the page's steps within each stage) as a second part. The GM:

> Yes, please do that, and please do include the per step counts. And then when you add the new section at the end, which is the table showing each stage and the counts, I would like to be able to click on one of those table rows to expand it to show a breakdown of the per step tallies, and then they should have their own percentages as well, where each step within a stage shows the number of function calls, the percentage of the stage that it is, and then the percentage of the overall map generation that that step is. So please go ahead and build that. Thank you.

And, on where the table goes:

> The section at the end would come after the "Features this map does not have" section, in case that wasn't clear.
