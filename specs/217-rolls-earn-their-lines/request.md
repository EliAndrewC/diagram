> Now I am concerned about the fact that at a certain point, we ended up adding a whole bunch of map rolls which we turned out not to need. So is there some automated mechanism that we could put in that would fail the tests if new map rolls are added while giving us the ability to bypass that because it is essentially requiring us to document why these are necessary after consulting with the project guidelines, or something like that. I do not want to unintentionally and carelessly find ourselves with ten different village maps being rolled in our make done tests when, in fact, only two or three would do. So the question is how to make this something that is noticed and where there is a requirement for the future session to stop and then consult the project guidelines and to very carefully think through the implications and make sure to combine every different map role that can possibly be combined until we have reached the bare minimum that it is possible to achieve while still maintaining one hundred percent code coverage. So if it is literally ever possible for us to achieve one hundred percent code coverage in our make done tests, Without adding a new map roll to the unit tests. then we should always do that. And as per our project conventions and general software engineering principles, we should not rely on a simple instruction, but rather there needs to be some amount of automation in place so that if a new map roll is added, then that causes a test failure or something Unless we prove in some way that we have consulted the project guidelines and made a justification, done an audit or something. To be honest, I'm not really sure how to implement this. I don't want to run a subagent check every single time we run our unit tests because that will take time and tokens and such. And I don't think there is necessarily a mechanism by which we are able to restrict makefile targets from only being runnable from within a particular subagent. So I don't know that there is a good way for us to do something like require that we are only able to add a new role after the subagent check has said that it is okay, but I don't know. That is conceptually what we are going for. Does all of that make sense? What do you think? what would be a good way to accomplish this?
