- **Approach**: two of the task's parts, each measured before it was changed: `make carry` skips a pick that comes out empty (`rust/gate/crates/land/src/land/carry.rs`), and every program the guards ask runs with `GIT_OPTIONAL_LOCKS=0` (`rust/guard/shared/src/tool.rs`).
  - **The carry test, reproduced**, measured 2026-11-26 (the land crate's test binary built from HEAD, `--exact land::carry::tests::a_clean_carry_is_verified_and_says_so_in_one_line` run 100 times in a row on a 22-core machine): 3 red of 100 ALONE, so it never needed load; under 12 looping copies of the crate's whole 123-test suite, 13 red of 100 (the run of the loops-after line below; a first run counted 7 of 100 with its load stopped partway). Every red is the test's second carry answering 2 where 0 was wanted (`carry/tests.rs:88`).
  - **The cause is the wall clock, and the defect is the code's.** The test committed in the builder's worktree and carried it into a clone standing on the same parent. A cherry-pick onto the commit's own parent rebuilds the same tree, parent, author, author date and message, so its sha is the builder's exactly when the committer's second is the same too; the second carry then found the commit "already in HEAD's history". Across a second's boundary the pick has another sha, the second carry picks again, the pick comes out EMPTY (git exits 1, `CHERRY_PICK_HEAD` standing, nothing unmerged, nothing staged) and the carry said STOPPED, exit 2. Shown apart from the test, measured 2026-11-26 (a scratch repository and worktree, a commit, `sleep 1.1`, `git cherry-pick`, then `git merge-base --is-ancestor` and a second pick): not an ancestor, the second pick exit 1 with "The previous cherry-pick is now empty", the marker standing. In a real clone the pick never lands on the commit's own parent in its own second, so every second `make carry` of a carried commit stopped with a pick standing, which `make land` then refuses (`unfinished.rs`): the test passed for the case that does not happen.
  - **The fix.** `skipped_empty`: a failed pick, or a failed `--continue` after both sides were kept, that left `CHERRY_PICK_HEAD` with nothing unmerged and nothing staged is an empty pick; it is skipped (`git cherry-pick --skip`) and the carry goes to its END, verified as any other (nothing in progress, unmerged or staged, the commit's non-spec files in HEAD), saying `changes nothing in <tree>, whose HEAD <sha> already holds its changes - nothing to carry`, exit 0. A pick that refused to start leaves no marker and still stops; a continue a commit hook refused leaves staged paths and still stops (both pinned by the test that was there). The empty `--continue` is the same cause by another door: lines kept from both sides that equal ours leave the continue nothing to commit.
  - **The tests no longer read the clock.** The clean carry's test ends at its first carry. `a_commit_carried_twice_changes_nothing_and_leaves_no_pick_standing` gives the clone a commit of its own first, so the pick's sha is never the builder's; `a_commit_in_heads_history_is_not_picked` reaches the history answer by a fast-forward, where the sha is the same by construction; `lines_kept_from_both_sides_that_equal_ours_end_as_an_empty_pick_skipped` is the continue's door.
