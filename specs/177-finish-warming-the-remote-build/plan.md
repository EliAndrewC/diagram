# Feature 177 - plan

**Constitution Check** (`.specify/templates/plan-template.md` gate). Principle VI: every change
below is verified by a test, and the two that cannot be (a real CodeBuild timing, an S3 lifecycle
document) are verified by READING BACK the artifact and recording it. Principle X: the tree stays at
100% coverage and no file crosses 1,000 lines. Principle XIII: baseline taken in a detached
worktree before the first measurement is quoted. Principle XVIII: every guard touched keeps its
companion suite. Nothing here changes what the gate verifies, which is the spec's hard boundary.

## The shape

Five independent pieces. Only piece 3 costs money, and it depends on 1 and 2 being in the tree so
that the measurement measures the finished thing.

    1. the hooks-test stamp travels        buildspec/*.yml, buildspec/run.sh

## 1 - the `hooks-test` stamp travels (FR-001 to FR-004)

**What travels.** Two paths under the git common directory, both content hashes:
`<git-common-dir>/gate-green-hooks` (the whole-area stamp `make done` reads through
`gate-stamp.py --fresh hooks`) and `<git-common-dir>/hooks-test/<guard>` (the per-suite stamps the
`hooks-test` recipe reads). In the build the checkout is `repo/`, so the cache paths are
`repo/.git/gate-green-hooks` and `repo/.git/hooks-test/**/*`.

**The hazard this creates, and the fix (FR-004).** `run.sh` currently detects a restored cache with
`[ -d repo ] && [ ! -d repo/.git ]`. Putting a `.git` path in the cache makes `repo/.git` exist, so
the test fails, the set-aside is skipped, and `mv bootstrap repo` moves bootstrap INSIDE the
restored directory - build `a48b730d` exactly. The detection becomes "is there a real repository
here?", `[ ! -e repo/.git/HEAD ]`, which a cache holding only `.git/hooks-test/` and
`.git/gate-green-hooks` cannot satisfy.

**Why this is safe (FR-002, FR-003).** Both stamps hash file CONTENT only - `gate-stamp.hash_files`
salted with `GATE_RECIPE`, and `sha256sum` over `_hookdeps.py`'s derived set. A changed guard yields
a different hash and its suite runs. And the S3 cache is written only BY A BUILD, never uploaded
from a laptop, so a remote skip rests on a remote proof. FR-003 wants that checked rather than
argued: a test asserts that the dispatcher uploads nothing and that the only writer of the cache
location is CodeBuild's own POST_BUILD.

**Measurement**: the BUILD phase's `hooks-test` span, from the log, cold then warm.

## 2 - the checkout stops carrying what nothing reads (FR-005 to FR-007)

**The derivation** (research R4), and the burden is on each exclusion:

| path | MB | evidence |
|---|---|---|
| `.claude/skills/diagram/wip/*.html` | 190.8 | `render_cache.engine_fingerprint` and `gencache` both PRUNE `wip/`; the only `wip/` paths a gate phase touches are `.py` (ruff, `check-file-scale.py`), which STAY |
| `.claude/skills/diagram/dev/placement-stages/**` | 78.4 | a documentation artifact regenerated by `make placement-stages`; no test reads it |
| legacy NON-hamlet `*.svg` / `*.png` | 73.6 | **pending proof** - see below |
| legacy HAMLET `*.svg` / `*.png` | 97.9 | **STAYS.** `tests/test_villages.py` asserts every hamlets-tier bundle's PNG height against its own SVG viewBox, and `continue`s past a missing render. Excluding these would not fail; it would make the check pass while checking nothing |

**The roster-rot risk, and the guard for it.** An exclusion list is a roster, and this project's rule
is that a roster nobody can enumerate is one nobody revisits. So the list lives in ONE file, and a
test in `tests/tooling/` asserts that no engine or test module references a path under it - so a
future test that starts reading `wip/*.html` turns the gate red instead of silently skipping in the
build. That test is the answer to "how would we ever notice", and it is cheap because the list is
short.

**Mechanism**: `git clone --filter=blob:none --sparse` then `git sparse-checkout set --no-cone` with
`/*` plus one negation per row. `run.sh` applies it to the bootstrap clone before the checkout, so
the merge and the gate both see the reduced tree.

**Proof (FR-005)**: a GREEN remote build with the set applied. Nothing else counts.

## 3 - the measurement route, and the runs it exists for (FR-008 to FR-012)

**Why a route at all.** `decision.decide` evaluates `route-is-gated` for every mode and
`delta.is_engine()` excludes `ci/` by the GM's own FR-025 ruling, so this feature's delta -
`buildspec/`, `scripts/`, `ci/`, `specs/` - cannot dispatch anything. That is the wall 175 hit and
recorded; without a route, items 3 and 4b are undeliverable rather than merely awkward.

**Its envelope is CLOSED (FR-009a)**: it may bypass ONLY `route-is-gated` and
`green-local-since-edit`. `remote-enabled`, `breaker-not-tripped` and - for FULL - `door.py`'s
committed `permitted` entry all still refuse it. Modeled on `run_image`, which is already a paid,
prompted, logged dispatch outside the five conditions.

**It cannot mint a push credential (FR-009).** Enforced on the BUILD side: a third `MODE`, whose
`run.sh` branch writes no `verified/` record and never pushes. Not a flag the dispatcher promises to
set - a branch visible in the diff, which is the bar `door.py` set.

**The runs**, in order, each with its billed minutes and cost recorded to the run log:

1. reference, cold (cache deleted) - FR-020 and the cold baseline
2. reference, warm - FR-011, the post-174 number, against the local `make done` median (227.5 s)
3. FULL, cold - FR-012's cold side and the payload size read off the built object
4. FULL, warm - FR-012's warm side

~$1.50-$3.00 at $0.08/build-minute (A4). The prompt is answered under the GM's 2026-08-25
authorization, quoted in the logged reason so `make audit` can tell a session's answer from theirs.

## 4 - the lifecycle document (FR-013 to FR-015)

The live document (research R5) is a 14-day catch-all on prefix `''` plus the 30-day cache rule, and
S3 takes the shortest overlap, so `verified/` dies at 14 days. The change: replace the catch-all
with explicit rules per prefix that has churn, keep a catch-all at a long horizon so an unforeseen
prefix still cannot accumulate for ever (FR-014), and give `verified/` a horizon chosen for what
those records are FOR. `cachepolicy.py` owns the whole document rather than one rule, so
`put_bucket_lifecycle_configuration` - which overwrites - stops being a hazard, and its two open
questions for the GM are answered in place rather than left standing.

**Applied with the `[aws_admin]` credentials** (A1, verified), then READ BACK and recorded (FR-015).
The session key cannot even read the document, which is why 175 could not check its own assumption.

## 5 - the two found defects (FR-016 to FR-018)

**`main-tree-hooks.sh`** (FR-016, FR-017): add `(` to the `LEAVES` scan's command-position
alternatives. It widens what counts as LEAVING main, never what counts as a write, so a
`( cd /diagram && rm -rf x )` is still refused - which the suite proves alongside the case that
fails before the fix.

**`dispatch.cache_location`** (FR-018): key on the operation as well as the scope, so a
`TARGET=tripwire` run stops overwriting the reference gate's cache. The object count stays bounded -
operations are a registered finite set, not a per-commit value - which is the property FR-005 of
feature 175 exists to protect.

## Order of work

1, 2, 4 and 5 are independent and land first; 3 measures the result, so it goes last. Pieces 4 and 5
are the cheapest and carry no dependency, so they go first if anything blocks.
