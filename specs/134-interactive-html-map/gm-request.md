> Now that we have finally gotten our reference hamlet to the point where I'm really happy with it, then I would like to add the ability to have HTML be one of the things that we are generating in addition to an SVG that becomes a PNG file. I believe our project already talks about this as a future goal, and I think that this is a good time to begin work on that, especially since it can be done in parallel with other work. We can start with the reference hamlet specifically, though I expect that what we are doing is a generalized process that will kind of work for other hamlets as well. So the main thing that we need is to have the script, which is already storing coordinates and glyphs and such, to be able to result in an HTML page that has user interaction. The primary type of interaction that I want is being able to move my mouse over different parts of the map, and then that causes not only the thing that I have moved my mouse over to become highlighted, but actually for all other features like that to become highlighted. For example, if I highlight a farmhouse that I want all farmhouses on the map to become highlighted. If I highlight a flushing field, I want all flushing fields on the map to become highlighted. If I highlight the marshland or the scrubland, then I want all of the marshland or scrubland to be highlighted. However, it is important that we be able to highlight different categories of things and have them light up separately. For example, a farmhouse is not a shed, and a storage shed attached to a farmhouse is different than the animal sheds. where the animals are stored, etcetera. Similarly, the windbreak forest is different than the other patches of trees that are not part of the forest, and the bamboo patches, which are adjacent to many of the farmhouses, are different than the shared bamboo grove, which is close to the hamlet. So, basically, we have a lot of different judgment calls to make about what things get highlighted and which things do not. Additionally, there are sometimes things that are rendered inside of other things which we want to be highlighted. For example, we have rendered dark green plants that run along the earthen bunds which if memory serves our soybean plants, and it would be useful to be able to highlight them separately from the earthen buns being highlighted. Also? I think that because there are a bunch of different dry crops, then we probably want to be able to highlight the different types of dry crops separately. If a user clicks while a thing is highlighted, then we want to pull up a modal with an explanation of that thing. And when there are two different things which either overlap, such as plants which exist along those earthen bunds, or which are similar, such as different types of dry crops, then we want the explanation that pops up to reference the fact that these things are distinguished from one another. For example, if you highlight the windbreak forest and click on it and there is a different forest on the same map or different patches of trees, then the explanation which pops up should explain that this forest has a different purpose and was regulated differently, uh, and that the villagers interacted with it differently than they interacted with the other trees that can be found elsewhere. that sort of thing. Same with the different Categories of bamboo grudge. I think on our reference map, all of the village lanes are connected together, but if they were not connected, I would still expect them to all be highlighted and to be treated as a single feature. Also for things which are labeled, such as the notice board, then we want the label to be highlighted when someone mouse is over the notice board itself and vice versa. So that if someone mouses over the label, then the entity which is being labeled will also light up, and clicking on either one will result in the informational modal coming up. This seems like a large undertaking, which is worthy of a spec kit feature. So please proceed with that. Thanks.
