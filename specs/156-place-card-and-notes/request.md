# The GM's request, verbatim (2026-08-29)

Recorded unedited so the spec can be graded against it (constitution Principle XVI). Transcription
of a dictated message; the GM's own capitalization and slips are kept. Three are resolved rather
than silently edited: "Isashiro" is Inashiro, "models" is modals, and **"the town of Hawakawa" is
Hayakawa** - the GM names Hayakawa county in the same breath, and `pool/magistracies/`
already carries a `hayakawa-magistracy`. The resolution is recorded here so it is visible AS a
resolution (spec-fidelity, 2026-08-29).

<!-- SOURCE: GM NOTES - DO NOT MODIFY -->
I am looking at the HTML output for our reference hamlet of Inashiro. I'd like to make some changes to the content of the models which are pulled up when we click on various map features. First, I notice that the very first thing that is shown is whether or not something is historically accurate. And we almost always say that it is historically accurate. I would like to not explicitly say that things are historically accurate when they are because I want the presumption to be that things are always historically accurate unless stated otherwise. In other words, we should call out liberties that we have taken when we have chosen to deviate from historical accuracy. But in all other cases, we should simply say what A map feature is with the presumption of historical accuracy.

Also, I would like to be able to click on the title card for a settlement and then pull up an explanation of the type of settlement that this is. And I don't just mean saying that Inashiro is a hamlet. because there are different types of hamlets. And so the fact that this is a hamlet where rice is farmed, like, if this is the most common type of hamlet that exists or whatever, and we should give facts about the hamlet's population and such. For example, although someone could theoretically count the number of houses, we can say how many farmhouses there are and what the hamlet's total population is. Though, of course, we should use a tilde and say something like population ~75 to make it clear that these numbers are approximate. but we can say the types of crops. that are grown in the fields. and such. Basically, if someone clicks on the title card, I want to have a brief "what is this place" overview. In the case of a hamlet, then we should indicate that it is part of a village district. And, in fact, we should even say the direction of the village district. and other important things that are in the area. For example, if a hamlet is close to an Imperial Road, then we would say that. because this needs to be automated, then I think what that means is that the notes that exist for a particular settlement should be formatted in such a way that the scripted process, which generates the HTML map, is able to pull these details. This also means that I think most of our scripted hamlets do not currently have a specific village that they belong to.  Akagahara and Ikegami belong to the village district of Hoshigaoka, which is directly east of Ikegami and to the northeast of Akagahara.  An Imperial Road is directly south of both Akagahara and Ikegami.  Hoshigaoka is itself directly north of the same Imperial road, and is part of Hayakawa county, and the town of Hawakawa is further south of the Imperial road. these are facts which should be saved into the associated notes for each of those settlements since I believe we have markdown files where we store such things for each settlement such as ikegami.notes.md And if we need to have some sort of well formatted or person conventions that allow us to put this kind of information in that file such that that information can be automatically pulled into the HTML file for a map in certain places, then that would be great. In fact, I think it would be good to have a generalized system for this, not only for the title card, but for other map features. For example, if we click on the village lanes then it would be good to be able to say where a village lane leads to. So for example, in our reference hamlet of Isashiro, We can note that the village lane leads towards the central village. This should be the default that a village lane leads to when not otherwise specified. Also, I have been referring to Hamlet lanes as village lanes specifically for this reason because they are presumed to lead into the main village when not otherwise stated. In cases like this where the village itself is unnamed, then you should invent a name for it. the gm-assistant repo Whose location should be known to you has an existing pool of place names that you can draw from. This is, in general, the kind of thing that we want to be able to do for any kind of map feature. So for example, if something was special about the windbreak for us on one specific map, then we would want to be able to annotate that in the notes file for that settlement. However, that will not usually be the case. So we should not presume that such sections exist and our code that parses the notes file to find these special notes. should be resilient against that formatting not being present. and should default to simply not pulling anything in if the parsing fails.

## Follow-up rulings, 2026-08-29 (during implementation)

Both arrived after the spec was approved and are recorded verbatim like the request itself. Neither
reopened the spec: the first corrects a figure's presentation, the second settles what the upper
tiers count - which FR-009 left to the tier and which nothing had yet decided.

<!-- SOURCE: GM NOTES - DO NOT MODIFY -->
You should not use a ~ for the number of farmhouses, because that actually IS an exact map feature - the number of farmhouses listed should be whatever is actually displayed on the map itself for hamlets and villages.
<!-- END SOURCE -->

<!-- SOURCE: GM NOTES - DO NOT MODIFY -->
Actually, towns and cities should state and list the number of non farmhouse dwellings. because this is something which is enumerated and known and which is actually exact and rendered. However, both towns and cities are surrounded by significant farm fields and farmer populations, which are deliberately not all rendered on the map. Therefore, that number should not be included. What we can do is list an approximate population for a town, which by convention includes the surrounding farming population, even though not all of this will be shown on the map. And for the city, which by convention does not include the surrounding farming population, this itself should be made clear when we eventually get to towns and cities. So for example, if we say that a town has a population of ~1,200 then we will make it clear that this includes the nearby farmers who are counted as being part of the town, Not all of which are depicted on the map, and if we say that a provincial city has a population of ~3,000 then we will explain that this includes samurai country estates, only some of which are depicted on the map, but does not include farmers. as each of the farms being shown belong to village districts and counties. which are administered and counted separately in the Imperial census.
<!-- END SOURCE -->

<!-- SOURCE: GM NOTES - DO NOT MODIFY -->
The default population of a town is already 1,200 So you can make that the population for all of the towns which we have already generated and document that. Though, again, that is the total population including farmers, which means that the sum total of that population is not visible on the map, which is intentional.

My ruling on the accuracy presumption is that we still do want to say where we have deviated and what we have guessed about. Thus, even when we are displaying something which we believe to be accurate, then if we had to guess or deviate from some documented source, then we should say so and explain why we did it.

To clarify how village districts work, the name of the village is the name of the village district. For example, Hoshigaoka village is the central village of the Hoshigaoka village district, and this name is always the same. To be clear, this is not historically accurate, but we have already documented that in our core role playing materials, and that deviation does not need to be mentioned in our maps. it is something that all players already understand, which I review with them This is explained in l7r.md in the core repository. So a village should never be listed as belonging to a village district with a different name. In fact, there is no reason to ever say what village district a village belongs to. because the name of the village is always the name of the village district. However, it does make sense to say what county a village belongs to because all villages belong to a county.
