# The GM's request, verbatim

2026-09-07, session "Diagram research", the first message after `/clear`:

> I love how extensive we are getting with our footnotes in our research. However, this is making the research pages fairly long. For example, research/homesteads.html within the diagram skill is already over one hundred and fifty kilobytes. And it's only going to get bigger as we add more questions and such. Now, obviously, the fact that we split things into multiple files is helpful, but I think that another version of that is warranted here. I think that we should have, inside to our research/ directory, a reearch/citations directory. This will allow us to have something like research/homesteads.html and research/citations/homesteads.html and then All of the citations at the end of a research file can be moved into the citations document. We should be careful to avoid duplicating content because currently the tooltips that we use when the mouse is moved over top of a footnote display the actual content. So if we did the naive thing and then split them into two places, then this would violate the don't repeat yourself principle. Instead, we probably need to do something like move our citations into a third location that can be loaded. by both of the different pages. something like a JSON file or a YAML file or even another HTML file, which has its own IDs that can be parsed and extracted. whatever seems best. In particular, I expect that in the long run, our footnotes themselves will probably grow longer because we already quote from the sources that we are referencing, and we may wish at a later time to expand those quotations or to also add more explanatory text around them, which summarizes the sources at a high level and that sort of thing. Therefore, whatever common place where we store these things should be in a format that lends itself to multi paragraph, well formatted text. So this could be something like Markdown or YAML. Or I suppose it could be JSON, though the lack of multiline strings makes this slightly annoying. Whatever you think is best.
>
> I would also like a List of what sources are being cited at the top of each citations page. For example, we have a number of different footnotes which cite "wang-ochiai-2022" and link to that source. Therefore, at the top of the citations page, before we begin listing the number of citations, we should list what this paper is, its name and its authors, and then a brief one two three sentence summary of what the paper is. We should additionally then have another one to three sentence summary of why we consider this a good and valid source. For what we are using it to look up. This explanation should include honest limitations. For example, some of our research may be from the year nineteen hundred, which is well within the modern era and well after the beginning of the industrial revolution. However, much of the land surveyed in China during that period was not yet industrialized. And, therefore, the comparisons to premodern societies are still quite useful. However, we should still be honest that there were modern agricultural techniques which would have been employed in the year nineteen hundred, which would not have been employed in our fictional setting or in the historical imperial Chinese periods and imperial Japanese eras. which we are using as a basis for our fictional setting. Similarly, We also cite sources that are about Korean rice farming. This seems fairly valid as Korea is from the same part of the world as China and Japan. Therefore, things involving crop yields and village sizes and things of that nature should be considered to be largely comparable. But we can still say that we use sources on Korea and Korean agriculture because we were not able to find publicly available sources that were more directly applicable. That kind of thing. Thus, each of our citations pages explains all of the sources that we are citing and then has multiple paragraphs of explanation about what those sources are and why it is fair to include them. Note that this is another place where we wish to avoid duplication because there will be multiple different research pages which each reference the same source, and we do not want to have multiple different write ups of a single paper. So for instance, if wang-ochiai-2022 (or any other data source, including wikipedia articles) ends up being referenced in our homesteads.html research and also in our fields.html research, We want to make sure that we are drawing from a single data source just as we want to be pulling from a single shared data source on both the research page and the citations page. Let me know if you have any questions about this. For example, if I have not been clear about what I'm expecting.
>
> We should also have a subagent check which runs anytime one of these new sources is being added. We can run this subagent check on each of our sources. as we add them down. hopefully, this will not result in any issues being uncovered. But, for example, if it turns out that we have used twenty first century forestry numbers, which would not be applicable to a premodern setting such as this, then this is the kind of place where that sort of subagent check will pay for itself either now or in the future when we are adding new sources. In fact, whatever subagent check we create in order to justify whether a source is applicable to be used in the creation of our diagrams, that subagent check should also be run when we first begin to make use of the source prior to integrating its numbers or claims or details into our maps. In that way, we might avoid, in the future, accidentally pulling in numbers or making use of sources, which should not be used to drive the creation of these maps and diagrams. That can be part of our procedures going forward.
